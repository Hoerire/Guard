# 自由启停（Guard）使用文档

Android 前台应用触发式禁用工具。进入指定「目标应用」时，自动批量禁用一组「禁用应用」（如 Magisk、KernelSU、MT 管理器、Termux 等），离开目标应用后自动恢复。全程事件驱动、按需执行，空闲开销趋近于零。

产物：`GuardApp-arm64-v8a.apk`（ARM64 原生架构，minSdk 26 / targetSdk 35）。

---

## 1. 核心原理

### 1.1 两段式架构

应用由两部分组成，职责分离：

| 部分 | 形态 | 职责 |
| --- | --- | --- |
| 自由启停 App | Java（`MainActivity`） | 配置管理、root 授权、服务拉起、脚本/终端、日志展示 |
| Guard | 原生 C 可执行程序（`guard.c`，`main()` 入口，非 JNI） | 前台监听、批量禁用/恢复、状态机管理 |

App 以 root 拉起 Guard，通过标准输出管道把 Guard 的实时日志回传到主页日志框；Guard 通过 `logcat -b events` 感知前台应用变化。

### 1.2 前台监听机制

Guard 订阅系统事件日志，只过滤两类窗口管理事件：

```
wm_on_resume_called
wm_on_top_resumed_gained_called
```

用 `poll()` 阻塞等待、按需消费，事件到达才唤醒处理。前台组件名经前缀匹配识别，兼容纯包名、`包名/类名`、完整类名三种形态，命中目标即批量禁用，离开即批量恢复。

### 1.3 禁用 / 恢复状态机

每个禁用应用维护一个 `AppState { pkg, was_enabled, modified }`：

- `was_enabled` 记录进入目标前该应用是否启用
- `modified` 记录本次会话是否真的被 Guard 改动过

禁用流程（`disable_pkg`）：先用 `pm path` 确认已安装，再用 `pm list packages -d/-e` 读取当前状态；已禁用则跳过。否则依次尝试 `pm disable --user 0`、`pm disable-user --user 0` 两种命令，每次执行后都重新读取状态验证，直到确认已禁用。

恢复流程（`enable_pkg`）：只恢复 `modified=true` 的应用，且只对原本就处于启用状态（`was_enabled=true`）的应用执行 `pm enable --user 0`。进程退出时执行 `cleanup()`，把所有修改过的应用恢复原状。

全局状态标志保证操作幂等：重复进入目标不会重复禁用，未进入目标时离开不会误恢复。

### 1.4 配置热重载

每次前台事件前，Guard 都会比对配置文件的时间戳与大小；有变化即热重载，**服务运行中重新勾选应用即时生效，无需重启服务**。配置解析采用原子方式：先解析到临时结构，全部成功后才生效，解析失败保留旧配置。

## 2. 功能详解

### 2.1 服务控制

- **root 授权**：启动即弹出授权框，通过 `su id` 校验；未获 root 提示「需要 Root 权限」并退出
- **服务状态卡**：状态圆点 + 「服务运行中 / 服务未运行」，副行显示 root 状态与目标/禁用数量；未授权时点击可重新请求
- **启动 / 停止合并按钮**：未运行时蓝色「启动服务」，运行中浅红「守护服务正在运行中」，点击即切换
- 启动流程：从 assets 强制覆盖释放 Guard 二进制（保证 APK 更新后立即生效），`chmod 755`，`su -c "Guard 配置路径"` 拉起
- 停止流程：`pkill -TERM -x Guard`，Guard 收到 SIGTERM 后执行 `cleanup()` 恢复所有被修改的应用再退出

### 2.2 目标应用与禁用应用

- **目标应用**：进入时触发批量禁用的应用，可多选
- **禁用应用**：进入目标后被禁用的应用，可多选
- **互斥规则**：同一应用不能同时是目标与禁用。App 端勾选时自动从另一列表移除（日志提示），Guard 端加载配置时若发现重复也从禁用列表剔除
- **应用列表**：按名称字母序，可搜索名称或包名；「显示系统应用」开关默认关闭（只显示用户应用）
- **勾选即保存**：勾选/取消自动写入配置，且已勾选应用自动置顶（取消后回到字母序原位）
- **配置识别**：打开 App 自动读取配置文件，把已保存的 target/freeze 包名自动勾选到对应列表（目标优先）

### 2.3 运行日志与导出

- 主页底部独立日志框：等宽字体、毫秒级时间戳（`HH:mm:ss.SSS`）、实时滚动
- 滚到底部时新日志自动跟随，向上翻阅时暂停跟随；日志框内部可独立滚动，不干扰主页滚动
- Guard 自身的时间戳前缀会被剥离，统一由 App 显示，避免双时间戳与空行
- **清空**：清空日志框
- **导出**：把当前日志导出到存储根目录 `/sdcard/Guard日志_yyyyMMdd_HHmmss.txt`。优先 root 写入绕过 Android 11+ 分区存储限制（先写应用缓存再 root `cp`，回退 root `cat` 直写，最后尝试普通写入），导出后任意文件管理器可见

### 2.4 脚本管理

- **路径浏览**：顶部输入目录路径（自动持久化，下次打开仍停留在该目录），点「打开」进入；下方以文件列表展开，文件夹在前、点击逐级下钻、「上一级」返回
- **列目录策略**：优先 Java File API 直接读取，读取受限时（`/sdcard`、`/data` 等）自动回退 root `ls`，任意目录均可浏览
- **运行脚本**：点脚本文件弹出运行确认，带「使用 SU 权限」复选框；勾选即 root 运行，否则以应用普通身份运行
- **交互式运行窗口**：顶部实时输出区 + 底部输入框。程序出现「请输入/选择」等提示时，在输入框输入数字或内容点「发送」即可，进程运行期间可随时发送
- **ELF 二进制识别**：读取文件头 4 字节，`7f 45 4c 46`（`\x7fELF`）即视为二进制可执行文件直接执行，不交给 `sh` 解释（避免把 ELF 当脚本导致乱码报错）
- **SU 模式执行链**：在 root shell 内读文件头判定 ELF——二进制则 `cd 目录 && chmod +x && exec`，否则 `cd 目录 && 补全环境 && exec sh 脚本`。`exec` 保证进程 PID 不因嵌套 shell 而变化
- **进程清理**：进程返回退出码后，统一关闭读取流、输入/输出管道并销毁直接进程，释放文件描述符、避免残留 shell 与僵尸进程；随后按 **cgroup** 定位并清理本次运行产生的**所有遗留进程**（包括但不限于 su、sh 及其子进程），先 SIGTERM 再 SIGKILL，日志输出「已清理所有遗留进程」并附各进程 PID（如 `PID=26809（sh）`），无残留时输出「无残留」
- **取消与失败区分**：手动关闭运行窗口导致的读取中断记为「已取消（进程被关闭）」，不误报为执行失败
- **ANSI 过滤**：所有脚本/终端输出自动过滤颜色与控制转义码，避免乱码

### 2.5 轻量终端

- 等宽字体黑底终端区 + 底部命令输入行（回车或「发送」执行），实时回显并自动滚动
- 已获 root 时以 `su -c sh` 进入 **root shell**（补全系统环境），否则回退普通 `sh`
- 会话在离开终端页后保持，返回可继续；顶部「清屏」清空显示
- 支持在终端内直接运行脚本（自带 ELF 判定与目录切换）
- 退出 App 时销毁终端进程

### 2.6 界面与交互

- **清新浅色毛玻璃风格**：浅色渐变 + 柔光大光斑背景，高透明白色圆角卡片带细描边与投影，图标统一浅色系
- **Apple 风格动效**：勾选、启动/停止、root 授权时底部弹性弹出悬浮胶囊提示；卡片/按钮/列表项「按下缩小、松开回弹」的 iOS spring 手感
- **工作原理**：应用内说明弹窗（两段式设计、事件监听、幂等状态机）
- **Bug 反馈**：优先跳转 QQ，未安装时回退浏览器

## 3. 配置格式

配置文件位于应用私有目录 `/data/user/0/com.example.guard/files/config.txt`（普通读写无需 root），格式：

```
# Guard config
interval:2

target:com.tencent.tmgp.sgame
target:com.tencent.ig

freeze:me.weishu.kernelsu
freeze:bin.mt.plus.canary
```

- `target:` 触发应用（进入时触发禁用），可多行
- `freeze:` 进入目标后被禁用的应用，可多行
- `interval:` 保留字段，当前事件监听模式不使用
- 以 `#` 开头的行为注释；非法包名被忽略并告警
- 配置文件不存在时 Guard 会生成默认配置，并以 `chmod 0666` 放开权限（root 创建的文件应用也能覆写）
- App 写入配置有三层兜底：直接写入 → 删除后重建（清理 root 残留文件）→ root 写入并 `chmod 666`

## 4. 构建与安装

### 4.1 构建产物

`build_arm64.sh` 完成完整构建：aapt2 编译/链接资源 → javac 编译 Java → d8 生成 dex → zipalign 对齐 → apksigner 签名。Guard 原生程序用 NDK clang 交叉编译为 `aarch64` PIE（动态链接 bionic），按 `minSdk 26` 构建。

### 4.2 安装与使用流程

1. 设备需已 root（Magisk / KernelSU / APatch 等，提供 `su`）
2. `adb install GuardApp-arm64-v8a.apk`
3. 打开自由启停，授予 root 权限
4. 进入「目标应用」「禁用应用」勾选（勾选即自动保存，已保存配置自动回显）
5. 点「启动服务」，Guard 开始监听；进入目标应用自动批量禁用，离开自动恢复
6. （可选）脚本管理浏览并运行脚本（可勾选 SU），或打开终端执行任意命令

## 5. 常见问题排查

| 现象 | 排查方向 |
| --- | --- |
| 日志出现 `[pm] ... 退出码=X` | Guard 的 `run_pm` 会打印每次 `pm` 命令的退出码与输出，据此判断禁用是否被系统拒绝 |
| 日志出现 `[警告] ... 命令退出码为 0 但状态未变` | 设备上 `pm disable` 被拦截（如厂商限制），已自动尝试 `disable-user` 备用命令 |
| 日志出现 `[自检] uid=...` | 启动自检行，确认 Guard 是否以 root 身份运行、pm 是否可用 |
| 禁用不生效 | 先核对「目标应用」列表：只有进入目标时才会触发禁用；确认配置热重载日志 `[配置已更新]` |
| 配置保存提示 EACCES | 配置文件残留 root 属主导致，App 会自动删除重建或改用 root 写入（`chmod 666`） |
| 更新 APK 后行为未变 | Guard 二进制每次都从 assets 覆盖释放，确认安装的是新 APK 即可 |

---

## 6. 注意事项

- 应用依赖 `su` 与 `pm`（shell 权限），必须在已 root 环境运行
- 禁用系统关键应用可能导致对应应用崩溃或系统异常，请谨慎勾选
- 停止服务时 Guard 会恢复本次会话中修改过的应用；若进程被强杀（SIGKILL），无法执行恢复逻辑，可用 App 重新启动后再停止，或手动 `pm enable` 恢复
- 脚本以 root 运行时拥有完整系统权限，请仅运行可信脚本
