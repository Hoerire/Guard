# Guard

Android 应用冻结/启停工具，基于 root 权限实现即时冻结与隐藏。

## 核心能力

### 冻结效率

Guard 采用 `pm disable/enable` 实现**即时冻结**，不依赖后台常驻服务：

- **一键切换**：点击主界面开关即可冻结或解冻全部目标应用，响应时间 < 1 秒
- **批量操作**：支持同时冻结数十个应用，通过 `pm disable-user` 统一执行，避免逐个调用 `am force-stop` 的延迟
- **零后台占用**：冻结后目标应用的进程被系统直接回收，不产生任何常驻进程、不消耗 CPU/内存
- **配置持久化**：冻结列表和禁用列表持久存储，重启后自动恢复上次状态
- **状态识别**：启动时自动识别当前配置（目标应用数 + 禁用应用数），无需手动检查

### 隐藏目的

Guard 的设计目标是**不被检测**：

- **无服务进程**：Guard 不注册任何 Android Service，冻结操作完成后进程立即退出，后台不留痕迹
- **进程清理机制**：脚本/二进制执行结束后，通过两段式清理彻底杀灭 su、sh 及所有子进程，不残留任何可被检测的进程链
- **二进制保留**：用户执行的独立二进制程序可选择性保留运行，清理时仅杀灭包装层（su/sh/终端），用户程序继续以孤儿进程方式独立运行
- **日志自管理**：所有操作日志存储在应用内，不写入系统 logcat 持久缓冲区，可随时清除
- **pm 方式优势**：相比 `am force-stop`，`pm disable` 使应用处于 `disabled` 状态，应用自身无法感知被冻结（不会触发 ANR 检测），解冻后正常启动无副作用

## 清理技术实现

脚本或二进制执行完毕后，Guard 执行**两段式进程清理**，确保无残留：

### Phase 1：快速杀（~0.1 秒，杀灭 95% 进程）

根据执行模式选择最快路径：

- **SH 脚本（不保留）**：`kill -9 -PGID` 一次内核调用杀灭整个进程组（含子进程、孙进程），这是最快的进程清理方式，仅一次 syscall
- **ELF 二进制（保留用户程序）**：`pgrep -P` 精确查找 su/sh 的直接子进程列表，跳过需要保留的二进制 PID，逐个 `kill -9`

Phase 1 覆盖正常进程树中的绝大多数进程。

### Phase 2：cgroup 扫描补杀（~0.3 秒，杀灭逃逸进程）

针对通过 `setsid`、`nohup`、管道 `|`、`daemon` 等方式脱离原进程组的逃逸进程：

1. 读取 `/proc/self/cgroup` 获取当前 cgroup 路径和 UID 段（`/uid_XXXXX`）
2. 遍历 `/proc/[0-9]*`，读取每个进程的 `cgroup` 文件
3. 匹配条件：cgroup 路径精确匹配**或**包含相同 UID 段
4. 直接 `kill -9`（SIGKILL），跳过 app 自身、preservePid、已知 PID、`$$`、`$PPID`

**关键优化**（相比传统方案）：

| 优化点 | 传统方案 | Guard |
|--------|---------|-------|
| 信号策略 | SIGTERM → sleep 1s → SIGKILL | 直接 SIGKILL |
| 扫描轮次 | 两轮（TERM + KILL） | 一轮 |
| sleep | 有（1 秒） | 无 |
| cgroup 解析 | `awk` + `sort` + `head` + `cut` 管道 | `awk` 单命令 |
| 匹配方式 | `cat` + shell `case` | `cat` + shell `case`（相同） |
| 总耗时 | 5-10 秒 | ~0.5 秒 |

### 清理触发时机

- **用户点击「清理」按钮**：立即输出日志，后台执行两段式清理，关闭弹窗
- **脚本自然结束**：执行线程 `finally` 块自动触发清理
- **进程异常退出**：`finally` 块兜底清理，确保任何情况下都不残留

## 使用要求

- Android 设备已 root（Magisk / KernelSU / 其他 root 方案均可）
- arm64-v8a 架构
- 需要授予 root 权限

## 架构

- 纯 Java 单 Activity 实现，无原生框架依赖
- 编译产物：classes.dex + 资源 + guard 二进制（arm64-v8a）
- 签名：内置证书自签名
