# 自由启停 · Guard

> 进入游戏自动隐藏 Root 工具，退出即恢复，全程零轮询、零卡顿。

**自由启停（Guard）** 是一款 Android 前台应用触发式禁用工具。当你进入指定的「目标应用」时，它会自动批量禁用一组预先勾选的敏感应用（如 **Magisk、KernelSU、MT 管理器、Termux、APatch** 等）；离开目标应用后，一切自动恢复原样。

- 🎯 **事件驱动**：订阅系统 `logcat events`，前台切换才触发，空闲开销 ≈ 0
- ⚡ **即时生效**：支持服务运行中修改配置热重载，无需重启
- 🛡️ **安全可靠**：状态机保证操作幂等；停止服务/崩溃退出时尽力恢复所有应用
- 🧰 **额外工具**：脚本管理 + 轻量 Root 终端，应急操作一站式

**产物**：`GuardApp-arm64-v8a.apk` · ARM64 原生 · minSdk 26 · targetSdk 35

## 🚀 快速开始（3 步搞定）

| 步骤 | 操作 |
|------|------|
| **1. 安装** | `adb install GuardApp-arm64-v8a.apk`（设备需已 Root） |
| **2. 授权** | 打开「自由启停」，在弹出的 Root 授权框中选择「永久允许」 |
| **3. 勾选** | 进入「目标应用」勾选你玩的游戏 → 进入「禁用应用」勾选要隐藏的 Root 工具 → 回到主页点「启动服务」 |

搞定！**现在打开你勾选的游戏，检查一下 Magisk App 是否真的消失；切回桌面，Magisk 应该又回来了。**

## 🧩 核心功能

### 📊 服务控制

主页顶部的状态卡实时显示：
- **Root 状态**（未授权时点击卡片可重新请求）
- **目标/禁用数量摘要**
- **服务启停按钮**：未运行时显示蓝色「启动服务」，运行中显示浅红色「守护服务正在运行中」，点击即切换

> 💡 **停止服务时会自动恢复本次会话中所有被修改过的应用**，不必担心残留禁用状态。

### 🎯 目标应用 + ❄️ 禁用应用

| 列表 | 含义 | 规则 |
|------|------|------|
| **目标应用** | 进入时触发批量禁用的「触发器」 | 多选，通常为游戏、银行、企微等检测环境的 App |
| **禁用应用** | 进入目标后会被「藏起来」的应用 | 多选，通常是 Magisk/KernelSU/MT/Termux 等工具 |

- **互斥保护**：同一应用不能同时在两边。勾选时会自动从另一侧移除，并输出日志提示
- **勾选即保存**：无需手动确认，勾选/取消立即写入 `config.txt`
- **应用置顶**：已勾选应用自动排到列表最前，方便核对
- **搜索与过滤**：顶部搜索框支持按名称或包名搜索；「显示系统应用」开关默认关闭（只看用户 App）

### 📜 运行日志与导出

主页底部独立日志框：
- **等宽字体** + **毫秒级时间戳**（`HH:mm:ss.SSS`），便于精确排查时序
- **智能滚动**：滚到底部时新日志自动跟随；向上翻阅时自动暂停跟随，不打断阅读
- **滚动冲突隔离**：日志框独立滚动，不干扰主页外层滚动

**操作**：
- **清空**：一键清空日志缓冲
- **导出**：保存到 `/sdcard/Guard日志_yyyyMMdd_HHmmss.txt`，优先 Root 写入绕过 Android 11+ 分区存储，任意文件管理器可见

### 📂 脚本管理

点击主页「脚本管理」进入：
1. **路径浏览**：顶部输入目录 → 点「打开」。默认进入 `/sdcard`，路径自动持久化下次打开仍在
2. **任意目录可读**：Java File API 优先，受限目录（如 `/data`）自动回退 Root `ls`，再深的路径也能进
3. **运行脚本**：点击脚本文件弹出确认框，可勾选「使用 SU 权限运行」
4. **交互式运行窗口**：顶部实时输出 + 底部输入框。遇到脚本提示「请输入选项」，输入数字/内容点「发送」即可随时响应
5. **ELF 自动识别**：自动检测文件头 `\x7fELF`，编译后的二进制直接执行，不交给 `sh` 导致乱码报错
6. **深度进程清理**：执行结束后按 **cgroup + PID** 双重归属扫描，清理 su、sh 及其所有子进程，先 SIGTERM 再 SIGKILL，日志中输出所有清理过的 PID，不留僵尸进程

### 💻 轻量终端

脚本管理页面顶栏入口 → 轻量终端：
- **Root Shell**：已授权时直接进入 `su -c sh`，补全系统 PATH/HOME/LANG/TERM
- **普通 Shell**：无 Root 时回退普通 `sh`
- **会话常驻**：离开终端页面后返回，进程仍在（可继续输入命令）
- **脚本直跑**：支持在终端中直接运行脚本，自动处理 ELF 判定与目录切换
- **ANSI 过滤**：自动剥除颜色与控制转义码，避免乱码
- App 退出时终端进程自动销毁

### 🎨 界面风格

- **清新浅色毛玻璃**：浅色渐变 + 大光斑背景，高透明白色圆角卡片 + 细描边与投影
- **Apple 风格动效**：按下缩小、松开回弹（iOS spring）；操作成功底部弹性弹出悬浮胶囊提示

## ⚙️ 配置格式

配置文件自动保存在应用私有目录：`/data/user/0/com.example.guard/files/config.txt`

```
# Guard config
interval:2

# ===== 目标应用 =====
target:com.tencent.tmgp.sgame
target:com.tencent.ig

# ===== 禁用列表 =====
freeze:me.weishu.kernelsu
freeze:bin.mt.plus.canary
freeze:com.termux
```

| 字段 | 说明 |
|------|------|
| `#` 开头 | 注释行，忽略 |
| `interval:<N>` | 保留字段，当前事件驱动模式不使用 |
| `target:<包名>` | 触发应用，可多行（最多 64 个） |
| `freeze:<包名>` | 进入目标后禁用的应用，可多行（最多 128 个） |

> 💡 **三层兜底写入**：普通写入失败 → 删除旧文件重建 → Root 写入 + `chmod 666`。无论 Guard 用 Root 创建了配置还是 App 自己写的，都能保证双方都能正常读写。

## 🔍 工作原理

### 两段式架构

| 模块 | 形态 | 职责 |
|------|------|------|
| **自由启停 App** | Java · `MainActivity` | 配置管理、Root 授权、服务拉起/停止、脚本管理、终端、日志实时展示 |
| **Guard** | 原生 C 可执行程序 · `guard.c` | 前台事件监听、批量禁用/恢复、状态机管理、配置热重载 |

App 通过 `su -c` 拉起 Guard，二者通过 **stdout 管道**实时通信（Guard 的日志逐行回传到 App 日志框）。Guard 独立于 App 运行，即使 App 被杀也不影响禁用逻辑。

### 事件驱动监听

Guard 启动 `logcat -b events` 子进程，**只订阅两类窗口管理事件**：
- `wm_on_resume_called`：Activity 进入前台
- `wm_on_top_resumed_gained_called`：顶层 resumed 焦点切换

用 `poll()` 无限阻塞等待 → **无事件时进程 CPU 占用 0%**。事件到达才唤醒 → 前缀匹配目标列表 → 批量禁用/恢复。

### 幂等状态机

每个禁用应用维护一个三状态：**`pkg` / `was_enabled` / `modified`**

```
进入目标应用
  └─> 每个 freeze App：记录 was_enabled → pm disable → 成功则 modified=true

离开目标应用
  └─> 仅 modified=true 且 was_enabled=true 的 App → pm enable → modified=false

收到 SIGTERM 退出
  └─> cleanup()：遍历所有 modified=true → 全部 pm enable
```

**关键点**：
- 重复进入目标：`active=true` 跳过，不会重复执行禁用
- 原本就禁用的 App：`was_enabled=false`，恢复时**不会误启用**（尊重用户原状态）

## ❓ 常见问题 FAQ

**Q: 禁用完全没反应？**
- 先确认「目标应用」真的勾选了：只有进入目标才触发禁用
- 查看日志是否出现 `[进入目标应用] 开始批量禁用`，没有说明前台事件没命中
- 确认 Guard 服务真的在运行，状态栏显示「服务运行中」

**Q: 日志里出现 `[警告] ... 命令退出码为 0 但状态未变`？**
- 这表示你的设备厂商 hook 了 `pm disable`，表面成功实际没禁用
- Guard 会自动 fallback 到 `pm disable-user --user 0`，看到下一行 `[成功] ... （命令 disable-user）` 就正常

**Q: 更新 APK 后 Guard 行为好像没变？**
- App 每次 `startService()` 都会从 APK 的 assets **强制覆盖释放** Guard 二进制到本地
- 确认安装的真是新 APK → 停止服务 → 再启动一次，即可生效

**Q: 配置保存失败，日志提示 EACCES？**
- 这是因为 Guard 首次启动时以 Root 创建了默认配置文件，属主为 root，App 普通用户无写权限
- App 会自动尝试：① 删除旧文件重建（目录权限仍保留）② Root 写入 + chmod 666，通常下一条日志就是 `[配置] 已保存(root)`，无需手动处理

**Q: 强制杀掉 Guard 进程，应用被冻结了没恢复怎么办？**
- 正常停止（`pkill -TERM`）一定会执行 cleanup，不用担心
- 如果被 `SIGKILL` 强杀（极端情况），恢复方式：
  - 方法 A：打开自由启停 → 启动服务 → 再停止服务（cleanup 会扫一遍恢复）
  - 方法 B：手动 `su -c "pm enable --user 0 <包名>"`

**Q: 脚本报错出现乱码 `ELF` 头？**
- 这是把二进制可执行文件误交给 `sh` 解释的典型表现
- 正常情况下自由启停的 **ELF 自动识别** 可以避免；如果仍出现，确认文件名是否正确、是否在 Root 模式下运行（/data 目录 Java 层读不到文件头）

## ⚠️ 安全与注意

1. **必须 Root**：本应用依赖 `su` 与 `pm`（Shell 级权限），未 Root 设备无法使用
2. **谨慎禁用系统应用**：禁用电话、Settings、SystemUI 等关键 App 可能导致系统崩溃或无限重启，「禁用应用」列表默认只显示用户应用，建议保持
3. **强杀风险**：只有 SIGKILL 无法捕获，正常的停止服务、App 退出、重启设备都不会导致永久冻结
4. **脚本安全**：以 Root 权限运行的脚本拥有完整系统控制权（包括可删除 `/data` 所有数据），**仅运行你绝对信任的脚本**
5. **分区存储**：日志导出到 `/sdcard` 时会优先用 Root 拷贝绕过 Android 11+ 分区存储限制；无 Root 时 Android 11+ 可能写失败，请手动授权存储权限
6. **本应用属自用工具**：无任何联网权限（代码里就没声明 INTERNET），不收集不传输任何数据
